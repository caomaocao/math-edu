# 实体图离线预生成，以判对规范名为键，emoji 只当兜底

全站实体类 emoji 逐步换成统一贴纸风的文生图素材（2026-07-28 家长带孩子四选一定的稿）。
生成只发生在开发机上：`tools/生成实体图.py` 调百炼 qwen-image-2.0（当时新上架、0.2 元/张、
RPM 120 免申请）出 2048px 白底图，`tools/抠白底.py` 洪泛抠透明 + 裁切缩到 256px，成品提交进
`web/shared/assets/实体图/`——线上代码永远不碰生成 API，因为断网可用是本站铁律，而且
百炼出图 URL 只活 24 小时，本来也存不得。

素材文件名与注册表（`web/shared/js/实体图.js`）的键是**素材名**——一个*视觉*实体的唯一
中文名；emoji 字符不稳（同一实体多个 emoji、平台字形不一）、英文名是附属说法，都不配当键。

**修订（2026-07-29，推广到全站时）**：最初这里写的是「键就是判对规范名」。推广时发现同一只
动物在不同环节有不同规范名——动物地图叫「狐狸」、树桩行列叫「小狐狸」，兔子更有「兔子 /
小兔 / 小兔子」三种叫法。照原样一名一图，同一只狐狸要生成两张互不相同的图，孩子在两关里会
看到两只狐狸。所以拆成两层：规范名仍是判对的主键、一个字不动，另设素材名作素材的主键，
**规范名 → 素材名 多对一**（归一表在 `实体图.js` 里）。查询函数对调用方的签名没变，仍然是
「给规范名，还回 URL 或 null」。反例要留神：动物地图的「小鸡」和树桩行列的「大公鸡」看着都
是鸡，却是两个视觉实体，各占一张图，不归一。环节数据里的 emoji 字段保留：`实体图(名)` 查不到就回落 emoji，运行时永不因缺图
崩（孩子继续玩）；但「该有图却没有」是红测试（`web/shared/test/实体图.test.js` 与磁盘双向
对账），跟缺英文台词同例，不许静默上线。

**修订（2026-08-09，第4讲蘑菇站）**：「篮子」是库里唯一一张**非正方**成品（680×285）。
模型给篮子画高提手的先验拦不住（提示词求了也没用），而蘑菇站要的是能横排一行已摘小蘑菇的
宽扁托篮——高提手正方图塞不下一行、还顶爆该站高度预算。所以这张出图后不走 `抠白底.py`，
由 `tools/裁篮子.py` 只裁前沿那一带落盘（原委在脚本头）。除它之外「256px 方图」仍是常态；
渲染方也不拿 `画实体` 的方形 `尺寸` 参数摆它，宽高比在第4讲 styles.css 的 `.篮框` 里按素材
实际比例写死。

## Consequences

- 换/补素材 = 重跑两个工具脚本再提交 PNG，一行运行时代码不用动。
- `.scratch/entity-art/` 下的 2048px 原图不入库（.gitignore），丢了可凭 seed 重生成。
- 宝藏环节拿 💰/💎/👑 字面字符当台词分支键、Boss 拿 🐲→💨 当状态标志——这两处把 emoji
  当主键用，与本决定冲突，推广到这些环节前必须先重构成具名键（见 .scratch/entity-art/issues/01）。
