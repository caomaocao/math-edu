# 公网性能优化：缓存分流 + gzip + 实体图 WebP + 进讲预热

2026-08-01 上线。目标是治 https://math.chongliangmango.com 上「开页慢、图片一张张迟到弹入」
的体感——本地开发时的秒开没跟着上公网。本文记录诊断、四项措施和实测效果；完整的盘问结论与
逐票实施记录在 `.scratch/speedup/`，ECS 侧的执行命令在 `部署到阿里云ECS.md`。

## 诊断（先量，再改）

对线上站实测（Chrome 网络面板 + fetch 探针），把「慢」拆成可归因的几段：

- **服务器无罪**。轻量应用服务器，2 核，峰值公网带宽 200Mbps；冷载 1.27MB 的 three.js 仅 66ms。
  带宽和 CPU 都不是瓶颈。
- **真凶：`no-cache` 全盖**。应用中间件给一切静态响应盖 `Cache-Control: no-cache`（本是给
  本机开发「改完刷新就见新」写的）。公网上后果是：暖缓存开一课 = **42 个请求全部 304 空校验**，
  每个一次完整往返，单张实体图空校验 300–556ms，整页 **1143ms**——本应接近 0。
- **次凶：nginx 未开 gzip**。1.27MB 的 three.js 裸奔过网线（`content-encoding: none`）。
- **图片弹入**：85 张实体图 PNG 共 5.2MB，按需加载，首次进环节时肉眼可见一张张冒出来。

## 四项措施

### 1. 缓存分流（`CACHE_PROFILE`）

一个环境变量把开发与公网分开，两套 `Cache-Control` 策略，一处代码：

- **`dev`（缺省）**：一切静态 `no-cache`——本机开发「改完刷新就见新」，一字未动。
- **`public`（ECS 上 `.env` 填）**：按 URL 路径分层——
  - 实体图 + vendored three.js → `max-age=86400, stale-while-revalidate=2592000`
    （素材变化少而慢，缓存一天 + 一个月 SWR；重生成的图最晚隔天到孩子眼前）。
  - 其余 JS/CSS/HTML → `max-age=0, stale-while-revalidate=604800`
    （每次都校验，但 SWR 让浏览器先用缓存秒渲染、后台静静校验；**发版下次打开必生效**）。
- 两种 profile 都以 `setdefault` 盖章，`/api/tts` 自设的一年缓存继续胜出。

**为什么 code 用 `max-age=0` 而不是给个小 max-age**：`max-age=0 + SWR` 保证「更新最晚下一次
打开生效」——每次开都问一句服务器，SWR 让这一问不阻塞渲染。给个 60s 的 max-age 会让窗口内的
更新连问都不问，反而牺牲发版及时性。

代码位置：`src/math_edu/settings.py`（读环境变量）、`src/math_edu/app.py` 的
`apply_cache_profile` 中间件（分层逻辑 + docstring 讲清取舍）。改缓存行为是 `.env` 编辑，
不是代码改动。

### 2. gzip（nginx）

只压文本类（css / js / json / svg；HTML 隐式已在），PNG/WebP/mp3 本就是压缩格式不碰。
**命门是 `gzip_proxied any`**：本站一切都走 `proxy_pass` 到 :8300，nginx 默认不压缩代理来的
响应，漏了这行 gzip 配了也不生效。配置在 `部署到阿里云ECS.md` 第 7 步的 nginx 块里。

### 3. 实体图全换 WebP

85 张 256px PNG → WebP（`cwebp -q 90` 有损，透明通道保真；先出松鼠/罗盘/礼物盒三张校样
目视比对再放量）。磁盘上只留一种格式，`.scratch` 里 2048px 原始底稿仍保持 PNG（中间态无损）。
渲染门（`web/shared/js/实体图.js` 里唯一的 URL 构造点）拼 `.webp`；抠白底管线
（`tools/抠白底.py`）末步直出 WebP，未来章节生成即得。缺图仍回落 emoji 兜底。

### 4. 进讲预热

进讲之后的空闲时段，把本讲会用到的实体图静静拉一遍，消灭首次进环节的弹入。
- `实体图.js` 的纯函数 `图清单(规范名[])`：去重 + 有图过滤 → URL 清单（走渲染门取 URL，
  与图片格式无关）。
- `web/shared/js/预热.js` 薄执行层：`requestIdleCallback` 空闲起步、并发 ≤4、`new Image()`
  拉取、任何失败静默（预热挂了孩子无感，环节照旧按需加载）；永不打断开场白与首屏。
- 每讲启动调一次：第3讲聚合各环节导出的 `实体们`，第2讲用调色板花名册（与覆盖测试同一接缝）。
  新增环节只要照旧导出 `实体们` 就自动被预热覆盖。

## 实测效果（改前 → 改后）

| 指标 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| 暖缓存打开第3讲导航 | 1143ms（42 请求全 304） | **150ms** | **7.6×** |
| 素材请求（webp/three） | 全部 304 空校验 | 43 个走缓存零网络 | — |
| 代码文件（JS/CSS） | 304 阻塞 | 25 个后台 304（各 ~300B，SWR 非阻塞） | — |
| three.module.js 传输 | 1,304,820 B（无压缩） | 269,731 B（gzip） | **降 79%** |
| 实体图总量 | 5.2MB（85 张 PNG） | 1.73MB（85 张 WebP） | **降 67%** |
| 首次进环节图片 | 一张张迟到弹入 | 预热后秒显 | 消除 |

线上响应头核验：罗盘.webp / three.js = `max-age=86400, stale-while-revalidate=2592000`；
说话.js = `max-age=0, stale-while-revalidate=604800`；gzip 生效；两讲实体图（第3讲 SVG 关卡
地图、第2讲 3D 贴纸贴图）渲染正常，0 张碎图、0 个 png 请求。

## 为什么不是 ADR

缓存分流可随时用 `.env` 回滚，WebP 可从 git 历史找回 PNG——都不满足「难以回头」。按家规不立
ADR；取舍理由写进了 `apply_cache_profile` 的 docstring 和本文。

## 维护提示

- 换模型/换域名不影响本文任何一条；缓存与 gzip 都在配置层（`.env` + nginx conf）。
- 新增实体图：跑 `抠白底.py` 直接得 WebP，注册表加名、环节 `实体们` 加名即可，预热自动覆盖。
- 想临时关掉公网缓存分流排查问题：ECS 上把 `.env` 的 `CACHE_PROFILE` 改回 `dev`、restart 即可。
- 验证命令（gzip 头、缓存分层头、dev/public 两 profile）在 `部署到阿里云ECS.md` 运维段。
