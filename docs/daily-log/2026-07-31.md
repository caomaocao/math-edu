# 2026-07-31 · 提速工程：一个提交装下四项措施

1 个提交（`52d7fa0`），但背后是一整天的诊断加实施——grilling 定稿的提速 spec + 6 张票
（`.scratch/speedup/`）当天全部落地，squash 成一次提交入库。

**诊断先行，数字说话**（详见 `docs/性能优化.md`，文档次日落盘）：轻量服务器 200Mbps
带宽无罪——冷载 1.27MB 的 three.js 只要 66ms；真凶是应用给一切静态响应盖 `no-cache`，
暖缓存开第3讲 42 个请求全部 304 空校验、整页 1.1 秒；次凶 nginx 没开 gzip。

**四项措施：**

1. **缓存分流** `CACHE_PROFILE`：本地 dev 保持 no-cache（改完刷新就见新），公网 public
   走 SWR 分层——实体图/three.js 一天硬缓存+一月 SWR，代码 max-age=0+一周 SWR。
2. **nginx gzip**（`gzip_proxied any` 是命门——全站都走 proxy_pass）。
3. **实体图 85 张全换 WebP q90**，管线直出，磁盘上只有一种格式（5.2MB → ~1.5MB）。
4. **进讲预热**：空闲时段把本讲实体图静静拉一遍，消灭首次进环节的弹入感——
   骑在「每环节导出 实体们」的既有接缝上，新环节免费获得预热。

后记（2026-08-03 补）：SWR 的逐资源 revalidate 没有模块图原子性，发版改跨文件 export 后
首开可能新旧混跑——账号体系上线当天真实咬了一口，已开票 `.scratch/speedup/issues/07`。
